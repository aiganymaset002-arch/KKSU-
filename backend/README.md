# Сервер KKSU на Supabase

Без сервера приложение работает в демо-режиме: все данные хранятся на одном устройстве.
С сервером у каждого пользователя есть свой аккаунт, а задания, оценки, чат, проекты и оплаты
видны на всех устройствах: ученик сдаёт работу на своём iPhone, педагог проверяет её на своём.

Supabase — облачная база данных с бесплатным тарифом (до 50 000 активных пользователей в месяц).

## 1. Создать проект (5 минут)

1. Зарегистрируйтесь на https://supabase.com (можно через GitHub).
2. **New project**: имя `kksu`, придумайте пароль базы и сохраните его. Регион — **Frankfurt (eu-central-1)**, он ближайший к Казахстану.
3. Дождитесь, пока проект создастся (1–2 минуты).

## 2. Создать таблицы и правила доступа

1. В проекте откройте **SQL Editor → New query**.
2. Скопируйте туда всё содержимое файла [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.
3. Должно появиться «Success. No rows returned».

## 3. Настроить вход и восстановление пароля

1. **Authentication → Sign In / Providers → Email**: включено.
   - **Confirm email** можно выключить на время тестирования. Если оставить включённым, пользователь сначала подтверждает email по ссылке из письма, потом входит в приложении.
2. **Authentication → Emails → Reset Password**: замените текст письма, чтобы в нём был 6-значный код:

   ```
   <h2>Восстановление пароля KKSU</h2>
   <p>Ваш код: <b>{{ .Token }}</b></p>
   <p>Введите его в приложении KKSU Online. Код действует 1 час.</p>
   ```

3. Для реальных писем подключите свой почтовый сервис: **Authentication → Emails → SMTP Settings**. Встроенная почта Supabase отправляет всего несколько писем в час.

## 4. Подключить приложение

Проект KKSU уже подключён в `KKSU/Core/KKSUCloud.swift`:

   ```swift
   enum KKSUCloudDefaults {
       static let projectURL = "https://vllechyeunbtozhubuud.supabase.co"
       static let anonKey = "sb_publishable_ThNRdPI2yoG1rQxLAiwusg_CmxF8Y7Y"
       static let schoolID = "kksu"
   }
   ```

1. Для другого проекта: **Project Settings → API Keys** — скопируйте **Project URL** и ключ **Publishable** (`sb_publishable_…`) или старый **anon public** (`eyJhbGciOi…`) и впишите их сюда.
2. Приложение работает через REST API Supabase напрямую (`URLSession`), пакет `supabase-swift` не нужен.

   Публичный ключ (publishable/anon) можно хранить в приложении: доступ к данным ограничивают правила RLS в базе.
   Ключи `service_role` и `sb_secret_…` в приложение **никогда не вставляйте**.

   Для быстрой проверки то же самое можно ввести прямо в приложении: «Сервер KKSU» на главной странице или «Модули → Сервер KKSU».

3. Соберите и запустите приложение.

## 5. Первый вход

1. **Первый зарегистрированный пользователь школы автоматически становится администратором.** Зарегистрируйтесь первыми.
2. Администратор: «Модули → Сервер KKSU → Загрузить стартовый учебный контент». Это программы, библиотека, тесты, курсы, партнёры, мероприятия и цены.
3. Ученики, родители и партнёры получают доступ сразу после регистрации. Педагоги, психологи, эксперты и наставники — только после подтверждения администратором на экране «Сервер KKSU».
4. Родителя привязывают к ребёнку в разделе «Пользователи и роли» (администратор) или при регистрации по email ребёнка.

## Как устроена защита данных

- Таблица `kksu_members` — участники школы, их роли, подтверждение и блокировка. Роль меняет только администратор.
- Таблица `kksu_records` — все записи приложения в формате JSON. У каждой записи есть список `visible_to`: кому она видна.
  - Работы, оценки, портфолио, анкета и согласия видны ученику, его родителям, наставнику и сотрудникам.
  - Сообщения видны только участникам диалога.
  - Уведомления и личные настройки видны только владельцу.
  - Программы, расписание, библиотека и курсы видны всей школе.
  - Задания, сгенерированные AI, видны только сотрудникам, пока педагог их не утвердит.
- Доступы к платному контенту, цены, промокоды и настройки оплаты меняют только сотрудники.
- Email и телефоны пользователей в общий каталог не попадают. Пароли хранит Supabase Auth.

## Что ещё нужно для полноценного запуска

- **Проверка покупок App Store на сервере.** Сейчас покупка подтверждается на устройстве. В продакшене транзакции нужно проверять через App Store Server API (Supabase Edge Function) и выдавать доступ с сервера.
- **Push-уведомления** о новых сообщениях и оценках: APNs + Edge Function. Сейчас уведомления приходят при синхронизации, примерно раз в 20 секунд, пока приложение открыто.
- **Файлы** (фото работ, чертежи, PDF) пока хранятся на устройстве. Для общего доступа их нужно загружать в Supabase Storage.
- Резервные копии: на платном тарифе Supabase они делаются автоматически.
